# 6. Rate Limiting с Nginx

Здесь мы используем NGINX для установки глобального Rate Limiting.

## Архитектура

```
┌─────────────────────────────────────────────────┐
│  External Request                               │
│  http://$(minikube ip):30002                    │
└────────────────────┬────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────┐
│  NodePort Service: nginx-lb-service             │
│  Type: NodePort                                 │
│  Port: 80 → NodePort: 30002                     │
└────────────────────┬────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────┐
│  Nginx Load Balancer Deployment                 │
│  - Rate Limiting: 20 req/min per IP             │
│  - Algorithm: Leaky Bucket                      │
│  - Burst: 20 requests                           │
│  - HTTP 429 on limit exceeded                   │
└────────────────────┬────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────┐
│  ClusterIP Service: nginx-backend-service       │
│  Type: ClusterIP                                │
│  Port: 80 (Round Robin to backend pods)         │
└────────────────────┬────────────────────────────┘
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
     ┌────────┐ ┌────────┐ ┌────────┐
     │ Pod 0  │ │ Pod 1  │ │ Pod 2  │
     │ nginx  │ │ nginx  │ │ nginx  │
     └────────┘ └────────┘ └────────┘
     StatefulSet: nginx-backend (3 replicas)
     
     (также есть Headless Service: nginx-backend-headless
      для DNS записей StatefulSet подов)
```

Здесь мы создаём StatefulSet на 3 пода, которые обрабатывают HTTP-запросы (в нашем случае -- просто выдают имя пода).
Мы создаём здесь ClusterIP, который правильно разрешает IP (работаая как round robin).
И мы используем NGINX, который будет обращаться к этому ClusterIP, а также ограничивать входящие запросы до 20 запросов в минуту.
NGINX будет использовать алгоритм Leaky Bucket, и "ведро" сначала будет пустым, тестировать нагрузку надо не раньше, чем через минуту после старта.
NGINX будет торчать наружу через NodePort по порту 30002 (т.е. будет доступен на `$(minikube ip):30002`).

**Лимит**: 20 запросов/минуту + burst 20 запросов (до 20 подряд, потом 1 каждые 3 сек)

## Основные компоненты [`nginx-statefulset.yaml`](nginx-statefulset.yaml)

### 1. Backend StatefulSet
- **3 пода** с nginx-серверами
- Каждый под возвращает "Hello from pod: {hostname}"
- Headless Service для DNS записей
- ClusterIP Service для доступа

### 2. Nginx Load Balancer
- **Round-robin** балансировка между 3 backend подами
- **Rate limiting**: 20 запросов в минуту на IP адрес
- **Алгоритм**: Leaky Bucket (встроенный в nginx)
- **Burst**: 5 дополнительных запросов для всплесков
- **NodePort 30002** для внешнего доступа


### Конфигурация nginx

```nginx
http {
  # Создаём зону для rate limiting
  limit_req_zone $binary_remote_addr zone=ratelimit:10m rate=20r/m;
  
  server {
    location / {
      # Применяем rate limiting
      limit_req zone=ratelimit burst=5 nodelay;
      
      proxy_pass http://backend;
    }
  }
}
```

### Поведение

**Нормальная нагрузка (≤20 req/min):**
- Все запросы обрабатываются
- HTTP 200 OK

**Всплеск (21-25 req/min):**
- Первые 20 запросов: обрабатываются
- Следующие 5 запросов: обрабатываются из burst
- HTTP 200 OK для всех

**Превышение лимита (>25 req/min):**
- Первые 25 запросов: HTTP 200 OK
- Остальные: HTTP 429 Too Many Requests

### Почему не стоит тестироваться из браузера?
Потому что при тестировании из браузера будут ещё попытки подгрузки favicon, т.е. страницу обновили один раз, а запросов ушло два
Логи -- см.  [`testing_with_browser.log`](testing_with_browser.log)

### ⚠️ Важно: Время восстановления burst

При `rate=20r/m` (20 запросов в минуту):
- Burst восстанавливается со скоростью **1 токен каждые 3 секунды**
- Для полного восстановления burst (20 токенов) нужно **60 секунд**
- Если делать тесты слишком часто → burst не успевает восстановиться

**Пример:**
```bash
# Первый тест: проходит 20 запросов (burst полный)
for i in {1..25}; do curl http://minikube-docker:30002/; done

# Второй тест сразу: проходит только 0-5 запросов (burst пустой)
for i in {1..25}; do curl http://minikube-docker:30002/; done

# Третий тест через 30 секунд: проходит ~10 запросов (burst восстановился на 50%)
sleep 30
for i in {1..25}; do curl http://minikube-docker:30002/; done

# Четвертый тест через 60 секунд: проходит 20 запросов (burst полный)
sleep 60
for i in {1..25}; do curl http://minikube-docker:30002/; done
```
